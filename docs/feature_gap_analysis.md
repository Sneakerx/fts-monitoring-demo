# IMF – Feature requests: analysis, implementation and traceability

This document traces the feature requests of the IMF ([`feature_request.txt`](../feature_request.txt),
written in instrument-independent terms; the FTS demo serves as the example). For each item it gives the wording, the gap found
in the original design, how the item is implemented and the test that verifies it. The design itself
is described in [architecture.md](architecture.md).

**Decisions taken**

* **Inputs.** Two product types, one per level: L0 (header information as catalogue attributes) and
  L1 (downloaded). L1 files are read as HDF5 or netCDF4 through format-generic readers
  (`imf/processing/readers.py`); the instrument adapter (`fts_reader.py`) maps the product layout.
  No ICDs exist yet: plausible synthetic layouts are generated by `pdgs_sim`. A real ICD replaces only the adapter.
* **Events.** The IMF detects the condition, raises an event with a recommended action and generates
  the proposed output (a value, a file or a command proposal). An expert approves or rejects it.
  The IMF never sends anything to the satellite or the FOS.

Status: ✔ implemented · ◐ implemented with assumptions (see section 6)

## 2. Requirements

| # | Requirement | Gap | Implementation | Verified by |
|---|---|---|---|---|
| R0a ✔ | Ingest two product types, one per level: L0 (header information only) and L1 (downloaded and read) | Dedicated product types per mission | `pdgs.product_types`: one type per level (validated); algorithms, analyses and rules refer to the level (`L0` / `L1`), not to mission product names | `test_algorithms::test_one_product_type_per_level`, `test_ingestion::test_poll_is_complete_and_idempotent` |

## 3. Events

| # | Requested event | Implementation (rule, kind) | Proposed output | Verified by |
|---|---|---|---|---|
| E1 ✔ | Non-nominal observation mode in the L0 header → calibration mode was run (event for the mission timeline) | `E1_CALIBRATION_MODE`, product rule on L0 | Timeline entry (INFO event), one per calibration (consecutive L0 products merged) | `test_rules::test_product_rule_calibration_mode` |
| E2 ✔ | Spectral calibration threshold reached → update the spectral calibration (laser wavenumber) | `E2_LASER_WAVENUMBER`, limit rule on `SPEC_SHIFT` | New laser wavenumber (value) | `test_rules::test_limit_rule_proposes_laser_wavenumber` |
| E3 ◐ | Radiometric feature detected with impact on the ISRF → update the radiometric scaling of the ISRF | `E3_ISRF_SCALING`, limit rule on `ISRF_FEATURE` | ISRF scaling factor (value) | 90-day scenario (day 85) |
| E4 ◐ | Delay between reference and science signal → update the complex transfer function | `E4_CTF_UPDATE`, limit rule on `REF_SCI_DELAY` | CTF phase correction (CSV) | `test_rules::test_limit_rule_ctf_update_file` |
| E5 ✔ | Offset drift (ZPD) → propose an offset correction | `E5_ZPD_DRIFT`, trend rule on `ZPD_OFFSET` | ZPD offset correction (value); implemented by operations, never sent by the IMF | `test_rules::test_trend_rule_zpd_raises_once_and_clears` |
| E6 ✔ | Quality index drift → propose an update of the spectral reference used for the L1 quality | `E6_NESR_DRIFT`, trend rule on `NESR_IDX_MEAN` | Draft of a new `NESR_TEMPLATE` version (CSV in the reference-data import format) | `test_rules::test_trend_rule_nesr_proposes_reference_update` |

Reprocessed baselines never trigger actions (`test_rules::test_reprocessed_baseline_triggers_no_actions`).

## 4. Demonstration scenario (90 days, simulator)

| Mission day | Injected condition | Visible as |
|---|---|---|
| 15.3, 47.6, 78.9 | calibration mode (L0 header `observationMode`) | E1, timeline |
| 30.2 – 30.7, 40 – 41 | PDGS outage, decontamination | timeline `DATA_GAP` |
| 45.0 – 45.3 | missing scans, L0 packet errors | `L0_SCANS`, `L0_PACKET_ERRORS`, `MISSING_SCANS` |
| 52.4 – 54 | cryocooler anomaly | `NESR_IDX*`, `NESR_B*`, `T_DETECTOR` (alarms; excluded from the E6 trend) |
| 60 – | slow ZPD drift (mechanism) | `ZPD_OFFSET`, E5 |
| 63.0 – 63.25 | L1 processing anomaly (B03 only) | `L1_COMPLETENESS` alarm, timeline `L1_GAP`; filled in reprocessing B04 |
| 65 – | thermistor degradation | `T_BENCH_STAB[TH]`, `T_SENSOR_CORR`, `T_SENSOR_DIFF` |
| 70 – 74 | metrology laser mode hop | `SPEC_SHIFT` → E2, `SSD` / `SSD_COMPLIANCE`, `ZPD_OFFSET` |
| 75 – | NESR drift (+0.4 %/day) | `NESR_IDX_MEAN` → E6 |
| 77 – | reference / science delay step | `REF_SCI_DELAY` → E4 |
| 85 – 86.5 | radiometric feature in the calibration window | `ISRF_FEATURE` → E3 |

## 5. Dockerfile assessment

The externally provided `Dockerfile` can be used as is for the demonstrator. It needs no change for
the new features: migrations live in the `imf` package, reference data in `config/`, and the new
dependencies (Alembic, netCDF4 – binary wheels exist for Linux) are in `requirements.txt`.

| # | Finding | Status |
|---|---|---|
| D1 | `DOCKER.md` was referenced but missing | Fixed |
| D2 | No `.dockerignore` (`.venv`, `data`, `.git`, `__pycache__` in the build context / image) | Fixed |
| D3 | Not reproducible: floating base-image tag and unpinned `requirements.txt` | Open – recommendation: pin by digest, add a lock file |
| D4 | Simulator and IMF in one container; the health check needs the simulator | Open – for operations: compose with `imf-web`, `imf-worker` (campaigns), PostgreSQL |
| D5 | `run_demo.py --reset` fails on the mount point; demo accounts | Documented in `DOCKER.md` |
| D6 | SQLite WAL on Windows bind mounts | Documented: named volume |

Docker was not available on the analysis machine, so the image build was not executed here.

## 6. Assumptions and open points

| # | Open point | Assumption in the prototype |
|---|---|---|
| O1 | Meaning of **SSD** | Spectral sampling distance 1 / (2·OPDmax); example requirement 0.625 cm⁻¹ ± 2.5 ppm |
| O2 | ICDs for the L0 header and the L1 product | Synthetic catalogue attributes / HDF5 and netCDF4 layouts (`pdgs_sim`) |
| O3 | Definition of the "radiometric feature with impact on the ISRF" | Largest relative depth outside the reference-line core in the calibration window |
| O4 | Source of the reference / science signal timing | L1 housekeeping `ref_sci_delay_us` |
| O5 | Formats of the reference update and the CTF update | CSV drafts (reference-data import format / phase table) |
| O6 | Number of quality-index sub-bands and spectral binning | 6 sub-bands |
| O7 | Archive ingested products or keep the hash only | Hash only (SHA-256 + PDGS id) |
| O8 | Baseline naming, nominal baseline switch after a campaign | `pdgs.baseline` in the configuration |
